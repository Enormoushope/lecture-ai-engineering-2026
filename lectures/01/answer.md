# 第1回 解答

## 演習

- 講座に固有の質問（宿題の3レベル）へのモデルの回答（要約でよい）：
	素のLLMは講座固有の情報を知らないため、「分からない」と答えるか、一般的な内容をもっともらしく答える可能性がある。
- 用語集の正しい意味と比べて気づいたこと：
	AIE2026の宿題は「基礎（講義内容の確認）」「実装（自分でコードを書く）」「発展（調査や試行）」の3段階で、どれか1つに取り組めば完了する。素のLLMの回答は、この講座固有の正しい定義とは異なる場合がある。
- 表示できたトークン数（入力 / 出力）：
	`uv run python -m app.ask "AIE2026の講座の宿題にある「3レベル」とは何ですか？"` を実行し、表示された値
    （入力: 50 / 出力:607）

## 宿題

- 取り組んだレベル：基礎・実装・発展
- やったこと：
	- 基礎：質問文を「AIE2026の講座の宿題の3レベルとは何ですか？簡潔に答えてください。」に固定し、`gemini-3.5-flash-lite` で temperature `0.0` と `1.0` をそれぞれ3回ずつ実行した。さらに、同じ質問を `AIE_MODEL=gemini-3.1-flash-lite` で1回実行し、モデルによる違いも比較した。
	- 実装：`app/ask.py` に `--chat` オプションを追加し、Gemini の Chat API で会話履歴を保ったまま続けて質問できるようにした。`response.usage_metadata` の `prompt_token_count` から入力トークン数を、`candidates_token_count` から出力トークン数を表示し、`time.perf_counter()` で応答時間も計測するようにした。
	- 発展：通常モードで上記の質問を実行した結果と、`--chat` モードで会話した結果を使い、モデル・質問・会話履歴による応答時間とトークン数の違いを比較した。
- 結果：
	- 基礎：`gemini-3.5-flash-lite` の temperature `0.0` では、1回目が入力26・出力122トークン、1.03秒、2回目が入力26・出力98トークン、0.97秒、3回目が入力26・出力124トークン、1.15秒だった。temperature `1.0` では、1回目が入力26・出力118トークン、1.32秒、2回目が入力26・出力121トークン、1.27秒、3回目が入力26・出力105トークン、1.02秒だった。どちらの温度でも「基礎・応用・発展」など一般的な3段階として回答し、講座の正しい分類である「基礎・実装・発展」には一致しなかった。`gemini-3.1-flash-lite` では入力26・出力176トークン、15.15秒で、こちらも一般的な説明だった。
	- 実装：`uv run python -m app.ask --chat` を実行した。初期質問は引数を省略したため既定の「AIE2026の講座の宿題にある「3レベル」とは何ですか？」で、応答は3.45秒、入力21・出力718トークンだった。その後「私の好きな色は青です。覚えておいてください。」と送ると0.80秒、入力752・出力36トークン、「私の好きな色は何ですか？」と送ると0.54秒、入力796・出力10トークンだった。最後の質問に「青」と回答したため、履歴が引き継がれていることを確認した。APIを使わない既存テストは7件すべて成功した。
	- 発展：通常モードでは、基礎の固定質問に対してモデルごとの応答時間とトークン数を比較した。`--chat` モードでは、初期質問への長い回答の後に短い記憶確認を行ったため、出力トークン数は718→36→10と減った。一方、会話履歴を毎回入力に含めるため、入力トークン数は21→752→796と増えた。
- 気づき・疑問：
	temperatureを変えると回答の表現や出力トークン数が変わったが、今回の範囲では正解には近づかなかった。temperature `0.0` でも回答が完全には同じにならず、APIやモデルの動作上、決定的な結果が保証されるとは限らない。別モデルの比較は1回だけなので、モデルの性能差と実行時の揺らぎを厳密には分離できない。会話モードの出力トークン数の差は、モデルが賢くなったからではなく、最初は講座内容を長く説明し、後の2回は短い質問に短く答えたためである。トークン数は質問やモデルによって変わり、トークンは文字数と同じではない。会話履歴を保つと、後の質問ほど入力トークン数が増えるため、料金や無料枠の消費も大きくなる可能性がある。今回の実行ではレート制限は発生しなかったが、同じ質問を何度も実行したり、長い回答を生成したりすると、無料枠のリクエスト数・トークン数の制限に達して429エラーになる可能性がある。

## 工夫した点・難しかった点・評価してほしい点

同じ質問をモデルやtemperatureごとに複数回実行し、回答だけでなく応答時間と入出力トークン数も記録しました。`--chat` を追加して会話履歴の効果も確認しました。SDKの設定方法と、入力トークンに履歴が含まれる仕組みの理解が難しかったです。条件と実測値を明記し、temperature 0.0でも結果が揺れるという限界まで考察した点を評価してほしいです。
